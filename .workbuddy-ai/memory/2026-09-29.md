## Render API v1 GOTCHAS (learned the hard way)
- POST /v1/services: non-static svc needs `serviceDetails` object. Put env-specific config
  (env, runtime, region, plan, healthCheckPath) INSIDE serviceDetails. Put `image`
  ({imagePath}) and `envVars` at TOP LEVEL.
- Top-level `envVars` in the create body was NOT reliably applied (backend got zero vars;
  only the one I later PUT landed). RELIABLE path: create svc, then set each env var with
  `PUT /v1/services/{id}/env-vars/{key}` body {"key":..,"value":..} (does NOT wipe others).
- List env-vars is CURSOR-paginated and nested: [{envVar:{key,value}, cursor}].
- `.env` with `VITE_SUPABASE_URL=https://<your-project-ref>.supabase.co` placeholder:
  `source`-ing it makes bash treat `<...>` as redirection -> "your-project-ref: No such file".
  Fix: extract vars with grep, never `source` the .env. Also VITE_SUPABASE_ANON_KEY was a
  `sb_publishable_...` placeholder; real value = SUPABASE_ANON_KEY (publishable key is safe
  for browser). Fixed both in .env.
